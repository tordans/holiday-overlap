# Plan: School and public holidays for Europe

Status: plan, nothing implemented yet. Research done 2026-10-18. Haiku agents tested the APIs with `curl` (including CORS with `Origin: https://example.github.io`). Lines marked **UNVERIFIED** still need a check against the official source before we ship data based on them.

## Goal and priorities

1. **School vacations longer than 5 days (weekends included)**, per region where a country staggers them. These are summer, autumn, Christmas, winter or carnival, and Easter or spring.
2. Public holidays (national and regional).
3. Bridge days (Brückentage): low priority. The existing `expandBridgeDayPeriods` keeps working on any public-holiday feed.

Today the app only supports Germany: [`src/lib/holidays/fetch-periods.ts`](../src/lib/holidays/fetch-periods.ts) calls `mehr-schulferien.de` per Bundesland ([`bundeslaender.ts`](../src/lib/holidays/bundeslaender.ts)).

## Key constraint

The app is a browser-only SPA on GitHub Pages, so a live source must:

- send `Access-Control-Allow-Origin`
- need no API key
- allow reuse under its license

Anything else becomes a **build-time snapshot** (a JSON file in the repo, refreshed by a script or GitHub Action) or **hand-curated data**.

## Implementation plan

### Phase 1: Source abstraction and OpenHolidays (largest gain)

- Introduce `HolidaySource` (`id`, `country`, `listRegions()`, `fetchPeriods(regionId, year, kind)`) and move today's code into `sources/mehr-schulferien.ts`.
- Generalise `bundeslaender.ts` into a `regions` registry: country → regions (code, label, optional group).
- Add `sources/openholidays.ts` with:
  - `/Subdivisions` and `/Groups` for region pickers
  - `/SchoolHolidays` and `/PublicHolidays` per subdivision
  - Zod validation of the responses
  - a filter that drops non-vacation rows (IT "floating holidays", "end of lessons")
- Add a **long-break filter**: keep a school period only if `end − start + 1 > 5` after extending to adjacent weekends (`date-fns`), with a toggle to show short ones.
- UI: a country selector before the region selector in `EditorDrawer`; the section title stays editable.
- Attribution: show source name, link and license (ODbL) next to imported data.

### Phase 2: France and the Netherlands

- `sources/fr-education.ts`: records API filtered by `zones` and `annee_scolaire`; pick region = zone (A/B/C, Corse, overseas); convert UTC to Europe/Paris. Public holidays from calendrier.api.gouv.fr (test CORS first), with an Alsace-Moselle variant.
- `scripts/fetch-nl.ts` (Bun) writes `src/data/holidays/nl.json`; the GitHub Action runs monthly and opens a PR on changes.

### Phase 3: Curated countries

- Schema `src/data/holidays/curated/<cc>.json`: `{ country, schoolYear, regions: [{ code, label, periods: [{ name, start, end, source }] }] }`, validated by Zod in a Vitest test.
- Fill BE (Flanders, FWB, DG), DK (week-7 and week-8 groups), IT and ES (start with the regions people actually ask for), SE/NO/FI (weekly sportlov/vinterferie groups, like CZ).
- Each entry needs an official `source` URL, which resolves the UNVERIFIED items above.

### Phase 4: Corrections and rest

- Correction layer for PL (and AT/LU if the checks confirm the conflicts).
- UK councils on request; GR and LV curated.

## Open questions

- ODbL share-alike: does showing OH data in a shared URL (`g=` state) count as a derived database? Probably only attribution is needed for display, but check.
- Do we cache across sessions (`localStorage` with a TTL) to stay polite to OH, whose rate limits are undocumented?
- How deep to go for municipally-varying countries (CH, DK, SE, NO, UK): canton or week-group level is probably enough for "is there overlap?" planning.
